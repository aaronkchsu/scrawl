# SCRAWL / Excavation

This repository owns only this project. Do not modify sibling captions files or read its .env.

Current product: a compact Twitch excavation game. Each viewer has an original small explorer at the bottom of the stream. Up to three viewers climb on foot in a narrow side lane, clear obstacles, and choose once to keep loot or risk the summit. Banked gear and XP persist. One or two Twitch channels share the climb queue; when both camps are waiting, starts alternate while preserving order within each camp. Keep can send a capped rescue rope to the partner camp. A fatal fall consumes that camp’s rope and banks collected loot without a summit crown. One rescue each way grants involved viewers a persistent cosmetic keepsake. The four-choice rescue practice is explicitly scripted and demo-only. Repeated commands never add queue entries or power.

Use original character art. Blerpy is a style reference only; do not include or trace those characters. The host interface follows the user's skills.sh reference: monochrome, block lettering, thin dividers, simple rows, plain copy. Explorers use the matching monochrome pixel-art atlas, with distinct silhouettes rather than hue shifts. Reserve color for loot and event feedback. The OBS background stays transparent.

Keep one Node 24 TypeScript server and browser-native HTML/CSS/JS. The server owns game state and overlays render its snapshots. Normal climbs use local rules. The host can explicitly spend one request to combine 3–6 distinct viewer ideas into a validated cave, two 16×16 pixel sprites, and one fixed route variant. Two camps create each other’s caves; solo creates its own. Preserve the existing request cap and ledger. No automatic generation on chat/climb, no viewer training or adaptive death odds. Retry retains the selected ideas, reset discards late results, and failed generation keeps the previous cave playable. Collected cosmetic finds persist separately from the current cave. Demo viewers and Hype events must be explicitly labeled simulated and isolated from live identities. Historical boss-game modules remain for reference but must not be wired into the new app accidentally.

Run npm run check and npm test after logic changes. Test persistence, queue fairness, held choices, duplicate events, reset/stale actions, Twitch reconnects, and save failures. Use browser QA for visible interactions, narrow layouts, and transparent overlays. Record actual evidence and limits in docs/build-log.md.

Submission footage must also show how Codex was used. When capturing a clip, update docs/storyboard.md with its file, what it proves, the relevant Codex implementation/testing evidence, and any missing shots. Preserve actual prompts, changes, failures and fixes; distinguish development assistance from in-game AI and simulated practice from real Twitch delivery.

Secrets stay on the server and out of git, logs, URLs, fixtures, screenshots, and browser bundles. Development binds loopback by default. The legacy local server requires CONTROL_TOKEN for remote control. Hosted mode uses Twitch sessions, room ownership checks and Postgres; never expose the legacy shared dashboard as public signup. OBS views are read-only. Keep the GitHub repository private until the user explicitly requests publication.
